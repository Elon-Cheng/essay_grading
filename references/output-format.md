# 前端输出结构与报告协议

本文件按当前三栏页面定义展示和 Markdown 导出契约。网页模型分别生成词句 JSON 和报告 JSON；程序用 grading_contract.py 的固定 schema 校验报告，并以原始段落和已校验词句批注确定性生成 Markdown，再解析成预览对象。模型不再负责原文复制、标题、修改标记和评分表。下文 Markdown 协议供程序渲染和离线 Word 使用，不加入网页模型提示词。


## 三栏与预览字段

| 页面位置 | 接口字段与要求 |
|---|---|
| 左栏作文题目 | prompt；中文题目和说明由程序放入题目区域，模型仍完整保留输入段落 |
| 左栏原文批注 | original 原始段落与 annotations 锚定；不使用报告改写后的 marked 替代原文 |
| 中栏词句批改 | annotations，三类同栏；模型字段按 web-annotations-prompt.md，id、start、end 由后端生成，偏移按 Unicode 字符计算 |
| 中栏逐段批改 | review.paragraphs，paragraph 保留原段号；feedback 使用内部标题，前端显示段落任务与内容逻辑／展开方法与训练建议 |
| 右栏综合评价 | review.overall 提取总分与参考表；review.evaluation.version=3，blocks 按全文规范顺序解析 |
| 局部中英文切换 | translations.en／zh 按点评原文匹配译文，由程序预生成保存；点击不调用模型，不能翻译标题、原文或评分 |

段落内部“段落点评”映射为“段落任务与内容逻辑”，“问题建议”映射为“展开方法与训练建议”。“语言提升”仅供 Word，前端逐段页签不展示；不要把页面显示名称写回 Markdown 协议标题。独立称呼、问候、落款敬语、署名、日期只使用“格式说明”，不生成段落点评或问题建议，不计入中栏逐段点评数。中栏仅展示有内容点评的开头段、正文各段和结尾段；题目和格式段保留在原始数据中，段落定位不重新编号。

右栏五块的解析字段依次为 comprehensive_sections（4项）、task_sections（4项）、cohesion_sections（5项）、lexical_sections（5项）、grammar_sections（5项）。准确标题和子标签只以 comprehensive-evaluation.md 为准。前端将“综合评价”显示为 Comprehensive Evaluation，将词汇五项中文协议标签映射成英文；模型不要据此修改内部名称。

原文标记和词句卡片都来自独立 annotations，不能从报告红色修改推导批注。两路完成状态放 channels.annotations／report，允许一路先显示；缺少字段时显示真实等待／失败状态，不编造卡片或评价。

## Markdown 协议

- 输出完整 Markdown，不用代码围栏或交付说明。可先用 `#### 审题情况` 加简短任务说明。
- 按输入顺序保留每个原始段落一次，包括题目、说明、称呼与署名，不合并、遗漏或重排。
- 每段以独占一行的 `#### 原文及红色修改` 开始，后面是完整原文及必要修改。删除用 `~~原文~~`，新增用 `{++新增++}`，替换用 `~~原文~~{++替换++}`。撤销标记后须逐字恢复原文，包括空格、标点、大小写和拼写；不直接用新句替代原句。
- 每个正文段后依次输出 `#### 段落点评`、`#### 语言提升`、`#### 问题建议`。用自然短段给具体分析与动作；语言提升解释相关语言问题和局部改法，不强制编号、表格或条数。
- 非正文、称呼、署名等无需完整反馈时，用 `#### 格式说明` 结束该段原文区块。正文用英文，例如 Keep the original text.；题目或说明不添加内容点评。
- 一个段落的原文和反馈完成后才开始下一段。可选优化不写入原文修改，不新增整篇改写稿。
- 文末用 `#### 全文综合评价和提升建议`，后接 comprehensive-evaluation.md 的五块及子项，最后仅一份总分和参考表。
- 内部标题及表头保持本协议名称，点评正文按 feedback-language.md 使用英文。四级标题只作解析标记，Word 用正文字号呈现。

## 总分与 A–E 表

总分行格式：`本篇文章打分估计为：18–19分`，分数按实际填写，满分25分。不显示分项得分明细，不生成第二份总评。

| 档次 | 内容 | 语言 | 组织结构 |
|---|---|---|---|
| A | 9–10 | 9–10 | 4–5 |
| B | 7–8 | 7–8 | 3 |
| C | 5–6 | 5–6 | 2 |
| D | 3–4 | 3–4 | 1 |
| E | 0–2 | 0–2 | 0 |

内容、语言、组织三列各用 `[[red]]…[[/red]]` 包裹一个实际对应分项单元格，共三处；分项可以命中不同档，不能按总分猜测。其他单元格、档次和表头不改。

网页报告 JSON 的 score 明确提供三个分项档位，由程序生成规范表。缺失分项不能根据总分补猜；原文从上传文件提取，不经过模型改写；独立 Error 是网页和 Word 的同一修改依据。旧 Markdown 与 RUBRIC_BANDS 仅用于兼容历史结果。

## Word 导出

程序生成的同一份 grading.md 供 Word 导出使用；原始底稿、配色及交付校验见 [word-export.md](word-export.md)。网页报告模型只输出 JSON，不输出文件步骤或校验说明。
