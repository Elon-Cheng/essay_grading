# 英语作文批改输入输出规范

本文件规定从学生 Word 作文到教师式 Word 批改稿的处理链路、内容结构和质量校验。

## 一、文件与转换链路

正式工作链路固定为：

`输入 DOCX → 原文 Markdown → 批改 Markdown → 最终 DOCX`

### 1. 原文 Markdown

从输入 DOCX 提取题目、学生信息和作文原文。必须：

- 保留全部句子、原始段落顺序、拼写、大小写和标点；
- 保留称呼、署名和学生原有分段；
- 区分学生原文、题目、已有教师批注和已有修订；
- 不把旧批注、评分表或教师修改混入学生原文；
- 不修复乱码后再假装是原文；无法可靠识别的字符须显式记录并回查 DOCX。

### 2. 批改 Markdown

批改 Markdown 是本次评分、修改和评语的唯一指导来源；原始 DOCX 是最终 Word 的版式与上下文底稿。批改 Markdown 必须包含：

- 位于第一段原文前的简短“审题情况”；
- 完整学生原文；
- 与原文位置一一对应的删除、替换和补充标记；
- 每个正文段落的段落点评、语言提升和问题建议；
- 全文综合评价和提升建议、本篇总分或合理分数区间，以及 A–E 分档参考表。

评分和任务判断先在内部完成，用于控制批改尺度；最终不输出“维度／得分／评价依据”明细表，只在文末呈现总分或合理分数区间及 A–E 分档参考表。

不得读取或修改旧输出 DOCX 来替代本次转换。批改 Markdown 不是用于另起空白 Word 的排版稿，而是用于定位原始 DOCX 中的作文段落并指导修改。

### 3. 最终 DOCX

最终 DOCX 必须复制本次输入的原始 DOCX 作为底稿，再由本次批改 Markdown 指导实际修改。不得通过复制、修改或重新打包旧输出 DOCX 冒充新生成结果，也不得脱离原始 DOCX 创建空白文档。

生成时必须：

- 保留原始 DOCX 中作文之外的题目、学生信息、说明、图片、页眉页脚、页面设置和可继续使用的样式；
- 在原作文段落所在位置应用红色删除、替换和补充，而不是在文末另贴一份修改稿；
- 将每段点评、语言提升和问题建议紧跟该原文段落，形成“老师在原文上指导修改”的阅读顺序；
- 从学生作文直接开始，将全文综合评价和提升建议、总分或分数区间及 A–E 分档参考表放在最后一段批改之后；
- 始终写入新的输出路径，不覆盖学生的输入 DOCX。

Word 中：

- 学生未修改的原文为黑色；
- 学生未改动的原文和被删除的原文英文保持黑色；
- 替换或补充的新英文为红色，不加下划线；
- 删除内容的文字保持黑色，并使用红色删除线；
- 中文批注、段落点评、语言提升、问题建议和局部示例为红色；
- 修改片段与下一句之间保留正常英文空格，禁止因 run 拆分而出现单词或句子粘连；
- 交付前逐处确认修改文字颜色、删除线颜色、无下划线和句间空格，并完成 DOCX 全部强制校验；
- 所有红色评语使用正文大小和正文段落格式；“段落点评”“语言提升”“问题建议”等标签可以加粗，但不放大字号，不使用多级标题视觉样式；
- 不生成完整 Revised Version；只允许在相关段落下提供必要的局部示例。

## 二、输出内容

最终批改不使用 A/B/C、Paragraph 1/2/3 等章节层级，也不设置文首分项评分信息块。第一段原文前只保留简短的“审题情况”。Content、Language、Organization 的分项判断只用于内部定档；成稿仅在文末呈现总分或合理分数区间及 A–E 分档参考表。

### 审题情况

- 有 `Structure`、`Outline`、`提纲` 或明确段落规划时，同时审核结构与全文：检查结构是否覆盖题目要求、顺序是否合理、全文是否落实结构。
- 没有结构或提纲时，只审核全文，不推测或补造结构。
- 写明正文实际词数，统计时不含称呼和署名。若低于 250 词或超过 300 词，明确写出：`本文约 __ 词，考场作文要满足 250–300 词。`
- 简要说明写作对象、交际目的、必答内容点和语体是否符合要求，不在此处展开语言纠错。

### 原文逐段批改

严格按原始段落顺序处理。每段只出现一次，并包含以下内容。

#### 原文及红色修改

- 保留该段全部原文；
- 每处修改只能对应原文中的唯一位置；
- 不得重复插入原句、漏句、交换句序或擅自拆分原段；
- 只有语法、明显词义或搭配、逻辑主语、指代歧义、题目明确要求等必须纠正的问题，才使用红色删除、替换或补充；
- 可选优化只写在语言提升或问题建议中，不直接改入原文；
- 内容较笼统但原句成立时保留原文，通过点评提示展开方向；
- 没有明显错误的段落原样保留，不为了产生红色痕迹而修改；
- 优先做保留原意的最小修改。多个错误相互牵连时才整句替换，并在语言提升中解释原因。

#### 段落点评

每段点评必须针对本段，说明：

1. 本段承担什么任务；
2. 哪些具体内容已经有效；
3. 最影响本段得分的问题；
4. 如何调整。

点评须引用或指向本段的具体内容，只评价内容与逻辑。禁止在段落点评中提及语法、词汇、搭配、句式、语言自然度或具体语言修改；这些内容全部放入“语言提升”。避免只写“逻辑不清”等空泛结论。尊重学生原意：如果一种问题可以通过删除预告、缩减承诺或局部重组解决，不要求学生为了形式强加新观点。

#### 语言提升

语言提升使用自然编号，不强制表格或固定条数。例如：

1. 这里缺少冠词，应改为：`invite a Hanfu expert`。此处指一位未特指的专家，单数可数名词需要限定词。
2. 原句 `I’m going to establish...` 语法可以成立，但申请语气不够正式，可改为：`I would like to propose establishing...`。

通常每段选择 2–4 个最有教学价值的问题；问题少时不凑数，复杂句可以把词义、指代和逻辑主语放在同一点中说明。每一点自然包含原表达、建议表达和中文解释即可。

批改者内部仍须区分：

- 必须纠正的问题：影响语法、含义、体裁或交际效果；
- 可选改进：原表达可以成立，但建议表达更自然、精确、简洁或符合语体。

上述分类只用于判断修改阈值，不作为成稿标签。成稿中禁止出现 `（错误：……）`、`（可选优化：……）` 或 `问题性质：……`；直接用自然语言说明原因。
语言提升不采用 `原表达 → 建议表达` 的机械格式。必须先说明具体问题，再使用“应改为：……”；仅属表达优化时使用“可改为：……”或“若想更……，可用：……”。

给出替换后，必须重新通读完整句子，检查：

- 语法结构是否完整；
- 主语和逻辑主语是否清楚；
- 原意是否保留；
- 搭配和语体是否自然；
- 替换是否造成重复、残句或新的错误。

不得只替换局部短语而留下不通顺的整句。

#### 问题建议

每个正文段落均设置“问题建议”，同时包含本段内容或逻辑上需要改进之处，以及由本段问题引出的学习积累建议。学习建议须具体可执行，例如阅读英文报刊并摘录完整词块、建立近义词和易混词辨析卡、按主题积累素材和例句、进行主语或指代专项检查；不得每段机械重复同一条建议。新增细节只能作为可选示例呈现。

#### 复杂句说明

如果整句需要替换，语言提升中必须分别解释关键词义、搭配、指代、逻辑主语或平行结构问题。不能只提供一条新句。容易混淆的词须解释差异和适用语境。

#### 简单格式问题

称呼、署名、姓名大小写等问题只使用一条红色批注，不单独展开“段落点评＋语言提升”表。正文段落仍使用完整结构。

### 全文综合评价

用一段自然的教师评语概括本篇：先说一到两个有证据的优点，再指出最影响提升的内容或语言问题，最后给出整体提升方向。不要复述各段点评，也不要写空泛套话。

### 文末评分与提升建议

将最影响本篇得分的 2–3 个问题整合进“全文综合评价和提升建议”。每个问题说明：

- 代表性位置或原表达；
- 影响的评分维度；
- 下次写作的具体训练方法；
- 一条可迁移的检查规则或表达。

随后用一行写出本篇总分或合理分数区间，再直接给出 A–E 分档参考表。严禁输出包含“维度、得分、评价依据、Content、Language、Organization、总分”的详细评分表。本部分不重复逐段语言反馈，不再写第二遍综合评价，也不提供整篇修改稿。分档表默认全部为黑色文字，只将本篇 Content、Language、Organization 实际命中的分数档位单元格标为红色，其他单元格和表头保持黑色。

## 三、转换完成后的强制校验

仅验证 DOCX 可以打开、ZIP 有效或存在红色字体，不足以证明转换正确。交付前必须完成以下检查。

### 1. 原文可逆校验

从最终 DOCX 的“原文逐段批改”中：

1. 删除所有新增和替换内容；
2. 恢复所有删除线内容；
3. 移除教师批注。

所得文字必须与原文 Markdown 的作文正文一致，包括句子顺序、段落边界和标点。若不一致，停止交付并重新生成。

### 2. 批改内容一致性

- 最终 DOCX 的段落点评、语言提升、综合评价和提升建议、总分或分数区间及 A–E 分档参考表必须与本次批改 Markdown 一致；
- DOCX 不得出现批改 Markdown 中不存在的旧评语或旧修改；
- 批改 Markdown 中的实质修改不得在 DOCX 中遗漏。
- DOCX 中按阅读顺序提取的全部标题、评语、表格字段和修改文字，必须与渲染器从批改 Markdown 得到的预期文字一致。

### 3. 原始底稿保留

- 最终 DOCX 必须能证明来源于本次输入 DOCX，而不是空白新建文档；
- 作文之外的原始内容及文档部件不得丢失；
- 作文段落在原位置被替换为带红色修改的同一段，未修改文字仍沿用原段落上下文；
- 输入 DOCX 保持不变，正式结果写入单独的输出文件。

### 4. 修改有效性

- 每处修改在原文中只有一个匹配位置；
- 修改后的完整句子语法成立、含义清楚、表达自然；
- 不出现重复原句、漏句、乱码、问号替代撇号或字面量 `\n`；
- 没有为了增加批改数量而修改正确表达。
- 原文中的每处红色修改都必须对应“错误”，不能只对应“可选优化”。

### 5. 视觉格式

- 原文黑色；
- 所有修改和中文批注红色；
- 删除线、下划线和补充文字含义明确；
- 原始段落保持完整，点评和语言提升紧跟对应段落。
- 红色评语使用正文大小，不出现放大的红色标题或 A/B/C 章节标题。
